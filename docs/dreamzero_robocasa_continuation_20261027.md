## 完整示范上的短程续训

三组从相同的最终 100k 适配器开始，先恢复原始 AgiBot 底座，再加载 LoRA 和投影层。
全部 814 个适配器/投影层张量与保存值逐项相等；训练参数总数为 108,582,944。
三个进程在初始 30 个诊断窗口上的采样指标完全一致。

- 训练：瓶子入柜任务的示范 0–11，沿整条轨迹选取 186 个完整的 24 动作窗口。
- 续训外诊断：同任务示范 12–15，每条取三个位置，共 12 个窗口。
- 跨任务检查：plate-to-plate 示范 12–15，每条三个位置，共 12 个窗口。
- 另在训练窗口中固定抽取六个位置监控拟合。
- 三组均使用 batch 2、200 次更新、LR 1e-6、AdamW、梯度裁剪 1、每步新噪声和时间步。
- 对照组是原始 video + action；第二组是 0.1 × video + action。
- 第三组保持 video 权重为 1，仅把动作时间步损失权重改为均匀的 1。
- 冻结编码器的输出缓存，关闭图像增强，每个窗口仅一个完整动作块。
- 这是使用新 Adam 状态的权重续训，不是恢复原优化器的精确断点续训。

这些示范都属于原 100k 训练数据，只有本次续训排除了诊断示范。
结果衡量的是本次续训的迁移情况，不是原模型在独立测试集上的泛化。
这里也不等价于原始 global batch 64、1–4 个块、多任务的完整训练。

采样使用当前首帧、当前状态、条件提示和原 16-UniPC/8-DiT 固定种子采样器。
不输入未来视频、未来状态或目标动作；目标动作仅用于误差计算。
没有使用仿真评测中的负提示和历史观测，因此后续仍需原生仿真验证。

续训外瓶子示范的前 8 步原始、未经限幅的归一化 MAE：

| 模型                      |     手臂 |     手部 |     腰部 |
| ------------------------- | -------: | -------: | -------: |
| 原 100k 适配器            | 0.048319 | 0.014919 | 0.028618 |
| 原目标续训 200 步         | 0.045795 | 0.016687 | 0.029230 |
| 视频权重 0.1，续训 200 步 | 0.045398 | 0.016872 | 0.028582 |
| 动作均匀权重，续训 200 步 | 0.047905 | 0.009432 | 0.030117 |

事先设定的筛选条件要求手臂改善至少 5%，且其他动作组和跨任务检查不恶化超过 10%。
三组都没有通过这个原始筛选：前两组手部归一化误差分别上升 11.85%、13.09%；
第三组手臂改善不足 5%，跨任务腰部误差上升 10.20%。
下面的指令空间复核修正了这些数字的物理含义；保留原始筛选结果，不事后修改门槛宣称通过。

## 实际指令误差的复核

发现最初指标包含超出 \[-1, 1\] 限幅范围的输出，以及 N15 坐标 25 这个常量手指维度。
仿真发送前会限幅并反归一化；该常量维度的 min/max 相同，预测值不会改变最终指令。
因此归一化误差的涨幅不能直接解释成控制指令同样幅度的退化。

重新使用生产路径的适配器加载函数加载四套权重，逐项确认 814 个张量完全一致，
再用同一批 24 个瓶子/plate-to-plate 窗口采样。指令误差为
`abs(clip(prediction, -1, 1) - normalized_target) * (max - min) / 2`。
手臂/腰部的单位是弧度，手部是控制器命令单位；常量坐标贡献为零。
另行保存排除坐标 25 后的手部归一化误差。

瓶子诊断窗口前 8 步实际指令 MAE：

| 模型                      | 手臂（rad） | 手部（命令单位） | 腰部（rad） |
| ------------------------- | ----------: | ---------------: | ----------: |
| 原 100k 适配器            |    0.069104 |         0.020498 |    0.009710 |
| 原目标续训 200 步         |    0.065273 |         0.020803 |    0.009906 |
| 视频权重 0.1，续训 200 步 |    0.064740 |         0.020411 |    0.009695 |
| 动作均匀权重，续训 200 步 |    0.068477 |         0.007375 |    0.010186 |
| 原适配器 + 手部组合投影   |    0.069104 |         0.015625 |    0.009710 |

- 原目标续训：手臂改善 5.54%，手部误差上升 1.49%。
- 视频权重 0.1：手臂改善 6.31%，手部基本持平。
- 动作均匀权重：手部改善 **64.02%**，手臂改善 0.91%，腰部误差上升 4.91%。
- 均匀权重的跨任务检查：手部误差从 0.163136 变为 0.163499（+0.22%），
  手臂 +1.75%，腰部 +7.65%。

这是事后更正的测量口径，不是新的预注册筛选。均匀权重因此进入一个瓶子场景的探索性验证，
并未被认定为已通过原筛选。该测量仍是专家观测上的动作误差，不能反映闭环偏移、
抓取时机和任务完成情况，也不能推断全任务收益。

末段原训练日志（90001–100000）的均值是 action loss 0.007794、video loss 0.032589。
标量损失比例不能说明两者对共享参数的梯度影响；上述实验没有证实视频目标是主要瓶颈。

## 动作时间步权重与手部组合实验

动作目标使用了原视频 scheduler 的时间步权重。检查 1000 个训练时间点：

| 噪声范围     | 采样比例 | 该范围的权重总量占比 |
| ------------ | -------: | -------------------: |
| sigma ≥ 0.99 |     4.9% |              0.1546% |
| sigma ≥ 0.95 |    20.9% |              3.1320% |
| sigma ≥ 0.90 |    35.8% |             10.1127% |

sigma=1 的权重恰好为 0，推理却从纯噪声启动。这也是上游实现的行为，
不是新发现的移植不一致。权重总量也不是实际梯度贡献。
第三组对照仅将动作时间步损失权重设为 1，保留视频权重、采样分布、输入、
学习率和 200 步训练计划。它不同于此前改变 sigma 采样分布的实验，结果见上表。

同时检查 24 个任务各自示范 0–11，共 288 条示范、72,505 步动作，发现左手只有
3 种六维命令组合，右手只有 2 种。左手包括全零的未激活模式。
`project_hands.py` 在归一化 N15 动作空间中选择最近的完整手部组合，
不是分别改变每根手指。它保留左手未激活模式和右手常量坐标。
所有观测到的示范指令投影后保持相同，手臂、腰部和 padding 逐位不变；
输入不会被原地改写，连续投影两次与一次相同。
这是一个独立的推理实验，用于检验连续手部输出是否影响抓取，不是已验证的训练改进。
24 任务单窗口检查中，前 8 步手部归一化 MAE 从 0.065846 降到 0.060764，
手臂和腰部完全不变。该投影仅存在于实验脚本中，未加入模型默认推理路径。

## 固定场景仿真结果

所有配对都使用启动前设置的 `PYTHONHASHSEED=7`，环境种子为 `7 + episode_id`，
原生历史观测、CFG、16-UniPC/8-DiT BF16 采样、每次执行 8 步、最多 720 控制步。
80k 与 100k 的 episode IDs 是 `[0, 100, 300, 900]`，对应任务 `[0, 2, 6, 18]` 的 trial 0。
手部投影使用其中 `[0, 900]`；均匀权重使用瓶子场景 `[0]`。

| 比较                    | 相同初始场景数 | 原 100k 成功数 | 候选成功数 |
| ----------------------- | -------------: | -------------: | ---------: |
| 80k vs 100k             |              4 |              0 |          0 |
| 100k + 手部组合投影     |              2 |              0 |          0 |
| 动作均匀权重续训 200 步 |              1 |              0 |          0 |

每个配对都校验任务描述、环境 seed、初始原始图像/状态指纹完全相同。
所有失败回合均运行至 720 步。均匀权重的瓶子场景仍失败，离线手部改善尚未转化为任务成功。
这是已知困难场景上的诊断，场景在不同比较中复用，不能当作独立的全套评测样本。
历史 80k 的 14.42% 仍值得受控复测，但本轮未证明它普遍优于 100k。

## 可直接评测的续训权重

已导出 `native_uniform/checkpoints/step-100200-uniform-action-bf16.safetensors`，
大小 45,848,616,944 bytes（约 42.7 GiB），同时保存匹配的 `dataset_statistics.json`。
权重中的 400 个 LoRA 矩阵由原 AgiBot 底座按
`BF16(base).float() + B @ A` 在 FP32 合并，再转为 BF16，另复制 14 个训练投影层张量；
其余张量保留原 100k 的值。rank=alpha=4，合并系数为 1。
这样仿真对照保持原生 BF16 权重精度，避免与未合并 FP32 适配器推理混为一谈。

文件名 100200 指原 100k 权重之后的 **200 次单任务、batch 2、新优化器更新**，
不代表完成了 200 步全量数据/global batch 64 续训。它是供复查的实验候选，尚无完整成功率。

`evaluate.sh` 提供 baseline/candidate 两种入口，使用同一个现有配置、不可变 checkpoint，
默认 24 任务 × 50 回合，并要求新的输出目录。激活 FluxVLA 环境后，可在本机运行：

```bash
DZ_BUNDLE=/mnt/data/cpfs/mnt/data/liyinhao/projects/fluxvla/dreamzero_fixes/20261027_continuation_pilot
PYTHONHASHSEED=7 NPROC_PER_NODE=2 WORLD_SIZE=1 RANK=0 bash "$DZ_BUNDLE/evaluate.sh" baseline "$DZ_BUNDLE/full_baseline_seed7"
PYTHONHASHSEED=7 NPROC_PER_NODE=2 WORLD_SIZE=1 RANK=0 bash "$DZ_BUNDLE/evaluate.sh" candidate "$DZ_BUNDLE/full_uniform_seed7"
```

多机使用相同命令和输出路径，并按现有 `scripts/eval.sh` 设置每节点的
`NPROC_PER_NODE`、`WORLD_SIZE`（节点数）、`RANK`、`MASTER_ADDR` 和端口。
换 checkout 时设置 `FLUXVLA_REPO`，并确认该 checkout 包含评测可复现性修复。
脚本已通过语法检查；本轮未运行这两组完整 1200 回合评测。

## 后续训练优先级

优先保留动作均匀权重作为多任务续训的对照项，保留原目标控制组并固定验证场景。
本次手部改善来自单任务小样本，不能据此直接替换正式 recipe；下一阶段需要覆盖所有任务的
训练外诊断、按实际指令记录分组误差，并以闭环任务成功来选择训练设置。
视频权重 0.1 有小幅手臂改善，也可作为次级对照；权重平均和手部投影目前证据不足。
原始标量 loss 继续下降并不是值得延长训练的充分依据。

## 本轮代码变更

`DDPTrainRunner` 新增 `lora_adapter_path`，可在原始底座上加载保存的适配器和投影层，
开启新的优化器与学习率计划。加载前核对 rank、alpha、目标模块、完整键集合和形状。
它不能与 `resume_from` 同时使用。现有合并导出的 `.pt` 不能被当作完整 PEFT 状态恢复；
错误使用现在会明确失败，避免 `strict=False` 静默跳过适配器。
这不等于为历史 LoRA checkpoint 补齐了精确断点恢复。

`DreamZeroHead` 新增 `dynamics_loss_weight`、`action_loss_weight`，默认均为 1；
`action_timestep_weighting` 默认仍为原始 `scheduler`，可显式选择 `uniform`。
分项损失仍独立记录；修改时间步权重后，训练 action loss 不能直接与旧值比较。
推理行为不随这些训练设置变化。

18 项针对性测试通过，包括适配器/投影层恢复、预测一致性、训练梯度、错误配置拒绝、
DDP 梯度检查点设置、真实小型 DiT 的前向/反向和采样，以及纯噪声点的动作梯度。
